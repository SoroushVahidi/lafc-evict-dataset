# Documentation Index

This directory mixes current public documentation with historical audits, handoffs, and planning records. New readers should start with the current documents below. Historical files are retained for reproducibility and decision provenance, but they are not current setup or release instructions unless they explicitly say so.

## Current Public Documentation

- [`LAFC_EVICT_PUBLICATION_STATE.md`](LAFC_EVICT_PUBLICATION_STATE.md): authoritative human-readable hosting and release-state overview for Hugging Face v1.0, AWS v0.3, and Zenodo v0.2.
- [`PERFORMANCE_EVALUATION_FINAL_SUBMISSION_STATE.md`](PERFORMANCE_EVALUATION_FINAL_SUBMISSION_STATE.md): final submitted Performance Evaluation manuscript package state.
- [`LAFC_EVICT_REPOSITORY_STATE.md`](LAFC_EVICT_REPOSITORY_STATE.md): repository state, canonical paper path, current release scope, and branch-cleanup cautions.
- [`SCIENTIFIC_EVIDENCE_INDEX.md`](SCIENTIFIC_EVIDENCE_INDEX.md): high-level scientific evidence map. Some entries are historical; prefer [`../analysis/README.md`](../analysis/README.md) for the current public analysis navigation layer.
- [`V0_3_V1_DATA_INVENTORY.md`](V0_3_V1_DATA_INVENTORY.md): data inventory and provenance notes; contains local absolute paths as historical audit evidence.
- [`WIKI2018_PROVENANCE_REVIEW.md`](WIKI2018_PROVENANCE_REVIEW.md): provenance and licensing review for Wiki2018.
- [`ZENODO_V0_2_PUBLICATION_RECORD.md`](ZENODO_V0_2_PUBLICATION_RECORD.md): archived v0.2 Zenodo publication record.

Release-facing dataset documentation lives primarily in [`../dataset_card/`](../dataset_card/), especially `DATASET_CARD.md`, `RELEASE_SCOPE.md`, `REPRODUCE.md`, `LICENSE_DATA.md`, `PROVENANCE.md`, and `SCHEMA.md`.

## Historical Development / Audit Records

Files with names such as `CURRENT_PROJECT_STATUS_AND_HANDOFF*`, dated prepublication audits, release design plans, rejection-risk crosswalks, and old v0.2/v0.3 planning records are preserved because they explain prior decisions. They may contain stale status, local paths, branch names, or workflow notes. Prefer the current public documentation above for present-day release and usage facts.

Do not delete historical records during routine public-polish work unless a later cleanup task explicitly authorizes removal.
