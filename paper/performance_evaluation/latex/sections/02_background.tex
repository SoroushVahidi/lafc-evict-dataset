\section{Background and a Worked Example}
\label{sec:background}

At each full-cache miss, a caching system must evict one resident object
before admitting the requested one. Classical policies such as LRU, ARC
\cite{megiddo2003arc}, and LIRS \cite{jiang2002lirs} operationalize this
choice through recency/frequency structure; more recent heuristics such as
SIEVE \cite{zhang2024sieve} and S3-FIFO \cite{yang2023s3fifo} revisit that
structure for scan-resistance and simplicity. A recent hybrid line tunes
such heuristics' own parameters with a learned control plane rather than
replacing them outright: LAH, instantiated as S4-FIFO over an S3-FIFO data
plane, reports robustness and interpretability gains from this
decoupling \cite{xia2026lah}. Learned or learning-augmented approaches (for
example LeCaR \cite{vietri2018lecar}, LRB \cite{song2020lrb}, Parrot
\cite{liu2020parrot}, GL-Cache \cite{yang2023glcache}, CACHEUS
\cite{rodriguez2021cacheus}, 3L-Cache \cite{zhou2025threelcache}, and HALP
\cite{song2023halp}) instead attempt to predict which eviction will lead
to lower future miss cost, typically by training on labels each system
derives for itself from raw traces. This makes cross-paper comparison hard:
different papers use different traces, different label constructions, and
different evaluation protocols, so a reported improvement is often not
attributable to the policy alone.

\lafc\ addresses the label-construction half of that problem by
materializing a reusable, candidate-level counterfactual label directly
from real traces, independent of any specific learned method. The rest of
this section works through exactly what that label is, using a small,
fully hand-checkable example (full derivation in the paper's
reproducibility artifact); Section~\ref{sec:benchmark-design} then defines
the same quantities formally for the production-scale dataset.

\subsection{A worked eviction decision}

Suppose a cache holds three objects at capacity 3, ordered from
least-recently-used to most-recently-used: A, B, C. A request arrives for
object D, which is not resident: a \emph{cache miss}. The cache is full,
so admitting D requires evicting exactly one resident object. A, B, and C
are the three \emph{candidate victims} for this \emph{eviction decision}.

To score each candidate, we look ahead a finite \emph{horizon} of $H=3$
future requests, which turn out to be B, E, F. For each candidate, we ask:
if this candidate, and no other, had been evicted, and the cache had then
continued to evict under a \emph{continuation policy} (LRU, the canonical
choice throughout this dataset) for the next $H$ requests, how many of
those requests would miss? This defines the candidate's \emph{counterfactual
miss cost}, stored as \texttt{y\_loss} (a convenience alias
\texttt{y\_value}~$=-\texttt{y\_loss}$ is also provided; see
Section~\ref{sec:benchmark-design}).

Figure~\ref{fig:worked-example} works through all three resulting
counterfactual worlds by hand. Evicting A costs 2 future misses (B hits
because A's eviction did not affect B; E and F both miss because they are
new objects). Evicting B costs 3 (B itself is now a miss, plus E and F).
Evicting C also costs 2, by the same reasoning as A. \textbf{The optimal
candidate set for this decision is \(\{A, C\}\), a tie} -- both evictions
are equally good by this measure, and only evicting B is strictly worse.
This is not a contrived edge case: across the full production dataset, no
audited decision has a strict unique winner (Section~\ref{sec:characterization}),
so tie handling of exactly this kind is the common case, not the
exception.

\subsection{From one decision to the released views}

Grouping every candidate row by its decision id gives the \emph{decision
view} (candidate count, optimal-set membership, tie flags, regret
summaries). Deriving pairwise preference labels directly from the
candidate-level \texttt{y\_loss} values -- e.g. this decision yields
(A,B): A preferred, (A,C): tie, (B,C): C preferred -- gives the
\emph{pairwise derived view}. The pairwise view introduces no new ground
truth: every label in it is a function of the candidate view already
described. This is a narrower claim than systems such as HALP, which train
directly on preference-comparison feedback as their primary learning
signal \cite{song2023halp}: \lafc's pairwise view is instead a
deterministic reformatting of the already-defined candidate-level
\texttt{y\_loss} values, released for compatibility with pairwise/ranking
methods rather than as an independent source of supervision
(Section~\ref{sec:tasks-baselines} discusses why a derived
pairwise view is still useful for certain modeling and diagnostic
purposes). A single full-cache miss with $k$ admissible candidates
therefore appears in three aligned forms: $k$ candidate rows, one
decision-group summary, and up to $k(k-1)/2$ within-decision pairwise
comparisons.
