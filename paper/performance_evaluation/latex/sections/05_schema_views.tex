\section{Dataset Schema and Views}
\label{sec:schema-views}

The canonical candidate schema currently consists of decision metadata, candidate identity, split information, labels, and feature columns. Each row corresponds to exactly one candidate victim at exactly one full-cache miss \emph{eviction event}, scored under one horizon. Trace identity and split metadata are recorded through \texttt{trace\_name}, \texttt{trace\_family}, \texttt{dataset\_source}, and \texttt{split}. Cache configuration is recorded through \texttt{capacity} and \texttt{horizon}. \texttt{decision\_id} identifies the underlying eviction event (trace, capacity, and request position) and is shared by every horizon at which that same event is scored; \texttt{decision\_t} gives its position in the request stream. The schema also records a per-decision chunk ID, \texttt{decision\_chunk\_id}. Candidate identity is represented through the field \texttt{candidate\_page\_id}. The labels are \texttt{y\_loss}, the finite-horizon counterfactual miss cost after forcing that candidate eviction under the fixed continuation policy, and \texttt{y\_value} $= -\texttt{y\_loss}$. Feature columns cover request context, candidate context, predictor/LRU signals, cache summary statistics, and recent request or hit rates.

Terminology used consistently for the rest of this paper: a \emph{candidate row} is one row of the base schema above (one candidate at one eviction event, one horizon). A \emph{decision} (interchangeably, \emph{decision-horizon instance}) is the group of candidate rows sharing the same \texttt{decision\_id} \emph{and} \texttt{horizon} -- since the same eviction event is independently scored at every evaluated horizon, one eviction event contributes one decision per horizon, not one decision overall. Reported decision counts (e.g.\ Table~\ref{tab:dataset-scale}) are therefore decision-horizon counts, pooled across all evaluated capacities and horizons, not counts of distinct physical eviction events.

Beyond candidate rows, the release defines two derived views. The \emph{decision view} aggregates all candidate rows that share a decision identifier \emph{and} horizon and summarizes each resulting decision with candidate count, minimum loss, maximum value, the set of optimal candidate IDs, tie count, and regret summary statistics. The \emph{pairwise view} compares candidate pairs from the same decision (same \texttt{decision\_id} and horizon) and derives pairwise preference labels from the ordering of their \texttt{y\_loss} values, with ties when the losses are equal. The evaluated open release does not ship the full pairwise view; it ships a capped pairwise sample of 1,000,000 rows instead.

Operationally, the schema can be read as a layered projection over the same eviction events: candidate rows are the atomic supervised objects, the decision view groups those rows by \texttt{decision\_id} and horizon, and the shipped pairwise sample keeps only selected within-decision comparisons.
