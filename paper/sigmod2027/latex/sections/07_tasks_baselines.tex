\section{Benchmark Tasks and Baselines}
\label{sec:tasks-baselines}

\lafc\ supports four benchmark tasks from one release.

\paragraph{Candidate-level value prediction.}
Predict \texttt{y\_loss} or \texttt{y\_value} from a single candidate row. This is a pointwise task over the canonical benchmark unit and measures how well a model predicts finite-horizon counterfactual eviction quality for one candidate at one decision.

\paragraph{Best-candidate selection.}
Given all candidate rows for one decision, identify a member of the minimum-loss set. This task can be framed as ranking or decision-level classification and connects most directly to the actual cache-eviction choice because it evaluates whether a method selects a benchmark-optimal victim within that decision.

\paragraph{Pairwise preference prediction.}
Predict whether candidate A is better than candidate B within the same decision, where ``better'' means lower \texttt{y\_loss} or equivalently higher \texttt{y\_value}. This task uses the pairwise view or the shipped pairwise sample and provides a simpler learning interface for within-decision preference modeling. Because equal losses induce ties, any paper using this task should state explicitly whether evaluation includes tie rows, excludes them, or maps them to a separate class.

\paragraph{Candidate-label distribution characterization.}
Summarize the empirical label surface without training a predictive model. This characterization task studies distributions of \texttt{y\_loss}, \texttt{y\_value}, regret, tie frequency, and decision ambiguity across families, capacities, horizons, and splits. It is descriptive rather than competitive, but it is important for understanding benchmark difficulty and for interpreting downstream task results.

The empirical scope of this draft is intentionally narrow. Rather than presenting a large model bake-off, we use the released task definitions to separate what the artifact already supports reproducibly from what would require additional candidate-row execution or feature joins. The manuscript therefore treats the current release primarily as a benchmark-definition and characterization contribution.

The only executed baseline results reported here are two non-feature sanity checks on the shipped pairwise sample: a majority baseline and a random baseline, both evaluated on the non-tie subset only. Because the shipped pairwise sample omits candidate-side predictor and LRU feature columns, these numbers test label balance and split behavior in the sample rather than the predictive power of cache-state features, and they should not be overread as end-to-end cache-policy evidence.
