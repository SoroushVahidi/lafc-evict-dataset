\section{Release Construction and Validation}
\label{sec:release-validation}

The release pipeline is designed to package existing generated candidate rows into a benchmark artifact without requiring raw traces in the release package. The builder uses an out-of-core DuckDB path to ingest candidate shards, normalize split values, emit partitioned Parquet candidate rows, derive the decision view, optionally create a capped pairwise sample, and write release metadata and checksums.

The validation surface is part of the benchmark contribution. The validation workflow includes:
\begin{itemize}[leftmargin=*]
  \item schema completeness for candidate partitions,
  \item split normalization and split-set consistency,
  \item presence of selected families and absence of blocked families,
  \item duplicate candidate detection within decision groups,
  \item consistency of decision metadata within a decision,
  \item decision-view schema and count consistency,
  \item checksum verification.
\end{itemize}

\begin{sloppypar}
The evaluated open-release snapshot passed metadata repair, the provided verification suite, publication-bundle validation, and end-to-end release validation. The validation evidence comes from manifest-backed counts, schema checks, split checks, duplicate detection, and checksum verification implemented in reproducible scripts. The manuscript therefore reports validation of the release package without relying on unpublished hosting details. It does not claim that final public hosting or DOI assignment is complete. It also does not treat superseded status notes as the authoritative source of scientific evidence.
\end{sloppypar}
