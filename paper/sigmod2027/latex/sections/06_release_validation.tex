\section{Release Construction and Validation}
\label{sec:release-validation}

The release pipeline is designed to package existing generated candidate rows into a benchmark artifact without requiring raw traces in the repository. The builder uses an out-of-core DuckDB path to ingest candidate shards, normalize split values, emit partitioned Parquet candidate rows, derive the decision view, optionally create a capped pairwise sample, and write release metadata and checksums.

The validation surface is part of the benchmark contribution. Current checks include:
\begin{itemize}[leftmargin=*]
  \item schema completeness for candidate partitions,
  \item split normalization and split-set consistency,
  \item presence of selected families and absence of blocked families,
  \item duplicate candidate detection within decision groups,
  \item consistency of decision metadata within a decision,
  \item decision-view schema and count consistency,
  \item checksum verification.
\end{itemize}

The preserved current-contract open release has passed lightweight metadata repair, repository tests, publication-bundle validation, and full real-release validation. The June 29, 2026 preserved-release validation run completed successfully with \texttt{exit\_status=0}. The validator CLI does not rewrite the release-internal validation-report markdown file, so that file still reflects earlier build-time paths and should not be treated as the authoritative June 29 validation record. For the anonymous SIGMOD submission, this means the manuscript can state that the preserved release passed end-to-end validation without relying on unpublished hosting or packaging details.
