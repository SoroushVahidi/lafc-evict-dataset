\section{Benchmark Design}
\label{sec:benchmark-design}

\lafc\ is organized around five layers: external raw traces, processed traces, generated features, generated labels, and benchmark tasks. The release in this repository begins after candidate-row generation and focuses on converting existing generated data into a reusable benchmark package for cache-eviction benchmarking, with schema, validation, and release metadata.

The current preserved open subset is \texttt{lafc-evict-v0.1-open}. The preserved current-contract release metadata identifies five selected families: \texttt{cloudphysics}, \texttt{metacdn}, \texttt{metakv}, \texttt{twemcache}, and \texttt{wiki2018}. The family registry also lists \texttt{brightkite} and \texttt{citibike} as excluded from the current open subset for redistribution reasons. This scope boundary is a release-governance decision, not a statement that the broader internally generated dataset is automatically redistributable. Not every selected family appears in every split in the current preserved release; for example, \texttt{metacdn} contributes train and validation decision rows but no test decision rows.

The canonical benchmark unit is the candidate row. A single row corresponds to one candidate victim at one full-cache miss decision, so one eviction decision with $|C_t|$ admissible victim choices contributes $|C_t|$ candidate rows. Decision-level and pairwise benchmark objects are derived from that candidate-level base rather than collected independently. This design keeps the benchmark centered on cache-eviction decisions instead of conflating the benchmark contribution with end-to-end deployment claims.

The benchmark is designed to satisfy four requirements:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Decision alignment.} Preserve within-decision structure and candidate competition.
  \item \textbf{Task multiplicity.} Support pointwise, decision-level, and pairwise learning tasks from one release.
  \item \textbf{Releaseability.} Separate public benchmark artifacts from upstream raw-trace ownership and hosting constraints.
  \item \textbf{Validation.} Expose checks for schema, consistency, family scope, and checksums.
\end{enumerate}
